# COACHING-L 音声リピートプレーヤー

端末内の好きな音声を使って、リスニング・シャドーイング・発話練習ができる日本語Webプレーヤーです。教材や音声の事前登録、アカウント、有料サービス、外部音声APIは不要です。

## 起動

アプリはビルド不要の静的サイトです。Node.js 22以降で、リポジトリのルートから実行します。

```sh
npm start
```

ブラウザで `http://localhost:4173` を開きます。ポートを変更する場合は `PORT=8080 npm start` を使えます。アプリの起動に `npm install` は不要です。別の静的HTTPサーバーでも利用できます。JavaScriptモジュールを使うため、HTMLファイルをダブルクリックする `file://` 起動は避けてください。

## 使い方

1. 「ファイルを選ぶ」で端末内の音声を選びます。パソコンでは選択エリアにドラッグ＆ドロップもできます。切り替える場合も同じ操作です。一度に開くのは1ファイルです。
2. 再生・一時停止、再生位置スライダー、5秒戻る／進むを操作できます。
3. 速度を0.5〜2.0倍で調整します。対応するブラウザでは `preservesPitch`（Safari系では対応する接頭辞付きプロパティも）を有効にします。声の高さや音質はブラウザの実装に依存します。音声の変換・書き出しは行いません。
4. 再生ゲージのA・Bつまみを左右へドラッグすると、色付きの範囲を見ながら区間を選べます。つまみは交差せず、ドラッグすると区間リピートがONになります。再生中はドラッグの間だけ停止し、離すと再開します。キーボードでは左右矢印で0.1秒、Shift＋矢印で1秒ずつ移動できます。ゲージ横のON／OFFと「今の位置をA／Bに」でも操作できます。A・Bの「現在位置を設定」で、再生中の位置を取り込めます。入力欄には `1:23.500` または `83.5` のように入力し、Enterまたはフォーカス移動で反映できます。`0 ≤ A < B ≤ 音声の長さ` を満たさない変更は反映されず、直前の有効な設定が使われます。
5. リピート範囲を「OFF」「A–B 区間」「音声全体」から選びます。OFFでもA–Bの値は残ります。A–Bモードでは再生位置の移動を区間内に制限します。
6. 再生回数を2・3・5・10回・無制限から選びます。**最初の再生を含む合計回数**です。例：2回なら「再生 → 無音 → 再生 → 停止」となり、最後に無音は入りません。区間途中から再生した場合、その終端到達を1回目に数えます。完了後の再生ボタンは区間先頭から新たな練習を始めます。リピート範囲・A–B・回数・無音時間の変更と区間呼び出しで回数をリセットします。速度変更や通常の一時停止では回数を維持します。
7. 無音時間を0〜10秒（0.1秒刻み）で指定できます。**実時間のタイマー**で待つので、0.5倍や2倍にしても指定秒数は変わりません。無音待ち中も一時停止でき、再開時は残りの無音時間を待ちます。
8. 区間名を入力して保存します。複数のA–B区間を、速度・回数・無音時間と一緒に保存できます。「呼び出す」でA–Bモードにして先頭で一時停止します。「削除」はその区間だけを削除します。

## 形式・プライバシー・保存

- MP3・M4A・WAVを優先し、ブラウザがデコードできるAAC・OGG・FLAC・WebMなども選択できます。拡張子が同じでも、内包コーデック・DRM・OSによって再生できないことがあります。非対応・破損・長さを取得できないファイルはエラーにします。
- 音声は `File` と一時的な `blob:` URLを通してブラウザで再生します。**アップロード、解析API、アクセス解析、外部CDN、外部フォントへの通信はありません。** ファイル切り替え時には再生と待機タイマーを止め、以前のURLを破棄します。
- ファイルごとの設定・名前付き区間は `localStorage` に保存します。保存対象にはファイル名・サイズ・最終更新日時も含まれます。音声本体や再生位置は永続保存しません。再訪問時はファイルを選び直してください。
- ファイルは「名前・サイズ・最終更新日時」の組み合わせで識別します。名前変更・編集・再ダウンロードなどで日時が変わると別ファイル扱いです。まったく同じメタデータを持つ別音声は同じ扱いになるため、その場合はファイル名を変えてください。
- 設定はブラウザ・サイトのオリジンごとです。別ブラウザ・別端末・別ドメイン・ポート間の同期はありません。ブラウザのサイトデータ削除で消えます。プライベートブラウズや容量制限で保存できない場合は画面で通知し、その画面内では練習を継続できます。共有端末ではサイトデータの扱いに注意してください。

## ブラウザとバックグラウンドの制限

最近のSafari・Chrome・Firefoxなど、HTML AudioとJavaScriptモジュールに対応するブラウザを想定しています。iPhoneは「ファイル」などのファイル選択から、端末にダウンロード済みの音声を選んでください。クラウド上だけにあるファイルは先にダウンロードが必要な場合があります。

A–Bの終端監視はJavaScriptで行います。前面表示でもタイマーやメディアのシーク精度によって数十ミリ秒程度以上のずれが生じる場合があり、サンプル単位の切り出しは保証しません。非常に短い区間は正確な練習に向きません。

**画面ロック、別タブ、別アプリへの移動、省電力状態では、特にiPhoneでタイマーや再生が停止・遅延することがあります。** 区間終端を越えて再生したり、指定した無音時間が延びる可能性があります。正確な区間練習には画面を開いた状態を推奨します。ページを離れる際は一時停止します。バックグラウンドでの正確なリピートは保証しません。ブラウザの自動再生制限により再生が止まった場合は、再生ボタンを再度押してください。

## テスト

開発用の依存関係をロックファイルどおりに導入して実行します。

```sh
npm ci
npx playwright install chromium webkit
npm test
npm run test:android
npm run test:safari
```

テストは静的サーバーを起動し、Playwrightでブラウザを操作します。`npm test` はデスクトップChromium、`npm run test:android` はPixel 7設定のモバイルChromium、`npm run test:safari` はデスクトップとiPhone 13設定のWebKitです。全プロジェクトをまとめて実行する場合は `npm run test:all` を使います。Linuxの `/usr/bin/chromium` がある場合はそれを使い、それ以外はPlaywrightで導入したChromiumを使います。明示的に指定する場合は `CHROMIUM_PATH=/path/to/chromium npm test` です。LinuxでブラウザのOS依存パッケージが不足する場合は、Playwright公式手順の `npx playwright install --with-deps chromium webkit` を利用してください。

テスト音声は外部教材を使わず、ローカル生成した交互のトーンです。WAVは `tests/fixtures/make-audio.mjs` でPCMを生成し、MP3・M4Aは同じ3秒の音をFFmpegでエンコードした小さなフィクスチャを同梱しています。実際のデコーダー、メディア時間の進行、再生・一時停止をテストします。APIをモックするだけの検証ではありません。自動再生を強制許可するフラグは使わず、速度測定も画面の再生ボタンを操作してから実施します。モバイル専用テストでは `tap()` によるファイル選択ボタン・再生・速度スライダー・無音待ち中の一時停止・区間保存の操作と、縦／横向きの幅を確認します。デスクトップ専用ドロップはモバイルでは対象外、タッチ専用テストはデスクトップでは対象外として明示的にスキップします。

対象：WAV・MP3・M4Aの読み込み／再生、0.5倍・2倍での実際のメディア進行速度、pitch維持フラグ、A–Bの2・3・5・10回停止、全体リピート、無制限、速度に依存しない無音時間、無音待ちの一時停止／再開、待機中のファイル切り替え、以前のURL破棄、不正入力、区間保存／再読み込み／呼び出し／削除／ファイル別管理、破損ファイルからの復帰、ドラッグ＆ドロップ、外部リクエストがないこと、保存不可時の継続、390px幅のレイアウトです。

検証結果・未確認事項は [検証記録](VALIDATION.md) を参照してください。Playwrightのモバイル設定は画面幅・ユーザーエージェント・タッチ操作などのエミュレーションであり、Android OSや実機Chromeの検証ではありません。WebKitはSafariと同系列のエンジンですが、Linux上のPlaywright WebKitで成功してもMac／iPhoneのSafari実機確認にはなりません。WebKitプロジェクトの実行状況は検証記録に明記します。音程維持は設定フラグを検証し、聴感上の音質や音程の測定は行いません。

### このクラウド環境でのブラウザ取得

WebKitの公式配信先 `cdn.playwright.dev` と `playwright.download.prss.microsoft.com` が環境のネットワーク許可リストに必要です。403 `Domain forbidden` が出た場合は環境設定の通信許可を反映してから再実行してください。アプリの通常利用にこの通信許可は不要です。この環境では書き込み可能な場所を指定して導入できます。

```sh
PLAYWRIGHT_BROWSERS_PATH=/tmp/audio-loop-browsers npx playwright install webkit
PLAYWRIGHT_BROWSERS_PATH=/tmp/audio-loop-browsers npm run test:safari
```

実機確認では、Mac Safari／Android Chromeで端末内のWAV・MP3・M4Aを選択し、0.5倍・2倍、A–Bの指定回数、無音待ちの一時停止、別ファイルへの切り替え、名前付き区間の再訪問後の復元を確認してください。OSのファイルピッカー・画面ロック・省電力時の動作はエミュレーションでは確認できません。

## GitHub Pagesへの配置手順（手動）

この実装作業では外部公開やデプロイを行いません。公開したい場合に、所有者が以下を実施できます。

1. このリポジトリのコードをGitHub上の公開対象ブランチに反映します。
2. GitHubのリポジトリ設定 → **Pages** → **Build and deployment** で **Deploy from a branch** を選びます。
3. 公開対象のブランチ（例：`main`）、フォルダー **/ (root)** を選択して保存します。
4. GitHubが示す公開URLを開き、ファイル選択と再生を確認します。

配信に必要なのは `index.html`、`style.css`、`app.js`、`player.js` と `icons/` です。すべて相対パスなので `https://<owner>.github.io/audio-loop-player/` のようなプロジェクトサイトでも使えます。Node.js、npm、サーバー側APIは公開先では不要です。テスト用音声はアプリに事前登録されず、利用者が選んだファイルだけを再生します。プライベートリポジトリのPages利用可否はGitHubの契約・設定に依存します。

## 構成

- `index.html` / `style.css`：日本語UIとレスポンシブ表示
- `app.js`：ファイルの寿命管理、入力検証、保存・呼び出し、画面更新
- `player.js`：再生状態、回数、無音待ち、タイマーの破棄、時間の変換
- `scripts/serve.mjs`：開発用の静的HTTPサーバー
- `tests/`：実音声を使うブラウザ回帰テスト

COACHING-Lのポモドーロアプリを基準に、同じロゴ画像、紺・金の配色、フォント、角丸、ヘッダー／フッター、モバイル優先の1列構成を採用しています。OSのライト／ダーク表示に連動します。参照元と共通化の範囲は [DESIGN.md](DESIGN.md) に記録しています。
